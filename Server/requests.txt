================================================================================
                          ATTENDANCE ENDPOINTS
================================================================================

1. CREATE ATTENDANCE (MARK PRESENT)
================================================================================
POST http://localhost:3000/api/v1/mentors/attendance
Content-Type: application/json

Body (raw):
{
  "internId": "60d5ec49c1234567890abcde",
  "mentorId": "60d5ec49c1234567890abcdf",
  "attendanceDate": "2026-04-11",
  "status": "present",
  "notes": "Student was on time and participated well"
}

Expected Response (201):
{
  "msg": "Attendance marked successfully",
  "data": {
    "id": "60d5ec49c1234567890abce0",
    "intern_id": "60d5ec49c1234567890abcde",
    "mentor_id": "60d5ec49c1234567890abcdf",
    "attendance_date": "2026-04-11T00:00:00.000Z",
    "status": "present",
    "notes": "Student was on time and participated well",
    "marked_by_mentor_id": "60d5ec49c1234567890abcdf",
    "created_at": "2026-04-11T10:30:00.000Z",
    "updated_at": "2026-04-11T10:30:00.000Z"
  }
}

                      VALID VALUES REFERENCE
================================================================================

ATTENDANCE STATUS (must match exactly):
- "present"
- "absent"
- "late"
- "excused"

MARK RANGE (inclusive):
- 0 to 100

DATE FORMAT:
- "2026-04-11" (YYYY-MM-DD)

PAGINATION:
- ?limit=10&page=1
- limit: 1-100 (default: 50)
- page: 1+ (default: 1)

================================================================================
                    RECOMMENDED TEST SEQUENCE
================================================================================

ATTENDANCE FLOW:
1. POST Create (present) → Save ID from response
2. GET by ID → Verify created data
3. GET by date → Check in date list
4. GET for intern → Verify pagination working
5. GET stats → Check breakdown by status
6. PUT Update status → Change to "late"
7. PUT Update notes → Add text
8. DELETE → Remove record

EVALUATION FLOW:
1. POST Create Week 1 → Save ID
2. POST Create Week 2 → Different week
3. POST Create Week 3 → Different week
4. GET all → Verify pagination
5. GET by ID → Check specific evaluation
6. GET search by name → Find intern by name
7. GET for intern → All three evaluations
8. GET stats → Average, highest, lowest marks
9. PUT Update mark → Change score
10. DELETE → Remove one evaluation

================================================================================
                        IMMUTABLE FIELDS
================================================================================

ATTENDANCE (Cannot be changed via UPDATE):
- intern_id (who was marked)
- mentor_id (which mentor assigned)
- attendance_date (the date)
- marked_by_mentor_id (audit trail - who marked it)

If you need to change these: DELETE and CREATE new record

EVALUATION (Cannot be changed via UPDATE):
- intern_id (who was evaluated)
- mentor_id (who did the evaluating)

CAN UPDATE: weekLabel, overallMark, feedback

Base URL: http://localhost:3000/api/v1

Variables to replace in all requests:
- INTERN_ID: 60d5ec49c1234567890abcde (replace with real intern's ID)

- ATTENDANCE_ID: 60d5ec49c1234567890abce0 (from create response)
- EVALUATION_ID: 60d5ec49c1234567890abce1 (from create response)

How to get real IDs:

- Create a mentor and copy their _id
